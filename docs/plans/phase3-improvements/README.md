## 사용자 정정 — 필수 테스트만 최소 실행

2026-11-16 사용자가 과도한 검증 범위를 지적했다. 아래 계획과 개별 문서의 대규모 벤치마크·반복 검증 요구는 자동 실행 대상에서 제외한다. 앞으로는 변경에 직접 필요한 최소 검사만 실행한다. 장시간 측정과 전체 매트릭스는 별도 명시적 요청 없이 재개하지 않는다. 진행 중이던 작업 전용 Docker 컨테이너는 중단했고 기존 결과는 보존했다. 3번의 측정 보고서와 4번의 공정성 평가는 완료된 것으로 표시하지 않는다.

## 공통 범위

- 기존 C17 엔진 `src/`, 루트 `Makefile`, 기존 C/CLI 테스트의 동작을 보존한다. 새 기능은 C++ 서버 계층에서 처리한다.
- 기존 HTTP 요청·응답 형식, INSERT 적용 여부, 결과 제한, 종료 시 작업 정리 계약을 유지한다. 지표는 추가하며 기존 필드를 없애지 않는다.
- 추가 전용 저장, 단일 writer, 모든 파일 변경이 이 서버를 통한다는 전제를 유지한다. UPDATE/DELETE, 외부 프로세스의 파일 변경, 트랜잭션, 자동 재시도, 인덱스 공유·주기적 재구축은 포함하지 않는다.
- 기존 미추적 `.omc/`, `docs/benchmarks/`, `src/.vs/`, `tests/bench_bptree.c`는 이번 작업 산출물과 구분하고 수정·삭제하지 않는다. 새 성능 결과는 `docs/phase3-benchmarks/`에 둔다.
- 실제 실행 전 브랜치·커밋·변경분을 다시 확인한다. 작업별 변경, 검증 결과, 남은 한계를 해당 계획에 기록한다.

## 검증과 결과 기록

- 코드 변경은 관련 단위 테스트와 Release HTTP 통합 테스트로 검증한다. 최종 회귀 검증에는 기존 `make test`를 포함한다.
- 동시성 변경에는 지원되는 환경에서 TSan을 실행한다. 런타임 시작 실패는 데이터 race 발견과 구분하며, 실행되지 않은 테스트를 통과로 기록하지 않는다.
- sanitizer의 OS, 컴파일러, 컨테이너 설정과 실제 명령을 기록한다. ASLR/컨테이너 보안 설정을 완화하는 방법을 기본 실행 조건으로 고정하지 않는다. 기본 환경이 지원되지 않으면 지원 환경을 사용하거나 미검증으로 명시한다.
- 정확성 테스트의 barrier/handshake에 시간 제한을 두되, sleep 시간이나 큰 파일의 처리시간을 실행 순서의 증거로 쓰지 않는다.
- 성능 수치를 correctness 테스트의 PASS 조건으로 사용하지 않는다. 기능 통과, 동시 실행 관찰, 성능 향상은 서로 다른 결과로 기록한다.
- 문서 변경만 있는 경우 링크·내용·`git diff --check`를 확인하고 불필요하게 전체 테스트를 반복하지 않는다.

## 완료 판단

1~3번은 각 계획의 완료 기준을 충족해야 완료다. 4번은 측정 근거를 포함한 정책 판단까지 필수이며, 판단이 '현재 정책 유지'이면 코드 변경 없이 완료할 수 있다. 측정이 없거나 재현 환경이 없어 판단할 수 없다면 '미완료/측정 필요'로 기록한다.

각 작업 결과에는 기준/결과 커밋 또는 미커밋 diff 식별, 수정 파일, 실제 명령, PASS/FAIL/미실행, 알려진 제한을 남긴다. 이 계획에 적힌 예정 결과를 실제 실행 결과로 옮겨 적지 않는다.
